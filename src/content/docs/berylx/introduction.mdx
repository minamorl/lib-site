`@minamorl/berylx` composes multistep workflows out of named tasks. Every task
is a function from a `Focus` on immutable state to a result: `Ok` with the
updated state, or `Err` with the partial state reached so far and a structured
error. Tasks compose in sequence, in parallel, by condition, and under recovery
handlers, and the composed workflow can be inspected, dry-run, or rendered as a
graph before it is executed. A `Root` owns committed state and commits a
workflow's result only when the whole workflow succeeds.

```ts
import { berylx } from "@minamorl/berylx";

interface Greeting {
  name: string;
  greeting: string;
}

const b = berylx<Greeting>();

const stripName = b.task("strip_name", (f) =>
  f.at("name").update((name) => name.trim()),
);
const greet = b.task("greet", (f) =>
  f.at("greeting").set(`Hello, ${f.at("name").get()}!`),
);

const root = b.root({ name: "  Mina  ", greeting: "" });
const result = root.pipe(stripName.then(greet));

result.focus.toObject(); // { name: 'Mina', greeting: 'Hello, Mina!' }
root.state(); // the same object: the root committed the Ok
```

This page documents version 0.3.0. It is a TypeScript port of the Ruby
[berylx](https://github.com/minamorl/berylx) gem; the execution engine is a
bundled TypeScript port of [darkcore](https://github.com/minamorl/darkcore-ruby).

## What it solves, and what it leaves to you

Berylx is for the shape of a workflow inside one process: which steps run,
in what order, what happens when one fails, and what state survives. It gives
you:

- one immutable state value threaded through every step, with typed path access;
- failure as a value (`Err`) that keeps the partial state and a machine-readable
  error, instead of a thrown exception that loses both;
- combinators with fixed semantics: `then` short-circuits, `par` joins with a
  three-way merge, `When`/`Else` selects an arm, `Catch`/`rescueWith` recover;
- a single commit point (`Root`) so a half-finished workflow never becomes
  observable state;
- structure you can look at: `Graph` for the shape, `EffectTree.dryRun` for the
  plan, and a handler map you can wrap for auditing or retries.

It does not persist state, schedule jobs, retry on a timer, or coordinate
across processes. Those belong to the application that runs the workflow.
Committing or rejecting state also does not undo external side effects a task
already performed; compensation is recovery logic you write.

## State: Focus

`Focus<S, P>` (alias `Lay`) is an immutable view of a root state `S` at a path
`P`. `at(key)` moves one level deeper without reading anything; `get()` reads
the value at the current path; `set(value)`, `update(fn)`, and `put(key, value)`
return a **new focus at the root** with the change applied. The original focus
is unchanged.

```ts
import { Focus } from "@minamorl/berylx";

const original = Focus.of({ user: { name: "  Mina  ", age: 21 } });
const updated = original
  .at("user")
  .at("name")
  .update((name) => name.trim());

original.at("user").at("name").get(); // '  Mina  '
updated.at("user").at("name").get(); // 'Mina'
updated.path; // [] — set/update return to the root

// @ts-expect-error 'nmae' is not a key of user
original.at("user").at("nmae");
```

The path is part of the type. `at` only accepts keys that exist at the current
path (`KeysAt<S, P>`), and `get` returns the type found there (`PathAt<S, P>`).
`set` must receive that same type: it never widens the state type, so declare
every field a later step will fill in your state interface.

Reading a path that does not exist throws `KeyError` from `get()`. The
alternatives are `get({ default })` / `fetch(default)`, `maybe()` (returns
`null`), `present()` (boolean), and `required(code?, message?)`, which returns
`Ok(this)` or an `Err` carrying this focus.

Plain objects and arrays given to a focus are defensively copied and deeply
frozen, so a caller mutating its own input afterwards does not change the
focus. `Map`, `Set`, `Date`, typed arrays, and class instances are kept as
supplied and their internals are not frozen.

## Results: Ok and Err

```ts
type Result<S> = Ok<S> | Err<S>;
```

Both carry a `focus` at the root. `Ok` is the updated state. `Err` is the
partial state at the moment of failure plus a `BerylxError` with `code`,
`message`, `failedNode`, `trace`, `parallelErrors`, `metadata`, `cause`, and a
`fatal()` flag. `Err` exposes the common fields directly (`err.code`,
`err.failedNode`, …).

A task fails in one of two ways:

- `focus.reject(code, message?)` returns an `Err` with that code and this focus
  as partial state. This is the domain-failure path.
- A thrown exception is caught and converted to an `Err` whose code is the
  error's `name` (`'TypeError'`, `'Error'`), with the exception in `cause`.

Nothing is unwrapped implicitly. `err.unwrap()` throws the original `cause` if
there is one, otherwise the `BerylxError` itself. Check with `isOk()` /
`isErr()` or `instanceof Ok` / `instanceof Err`.

```ts
const result = b.flow(state).call(workflow);
if (result instanceof Err) {
  result.code; // 'payment_failed'
  result.failedNode; // 'charge'
  result.focus.toObject(); // state as it was when 'charge' failed
}
```

A task callback may return a `Focus` at any path, an `Ok`/`Err`, or a raw
state object; each is normalised to a `Result`. Always return something:
a callback that returns `undefined` is normalised to an `Ok` over an empty
object, which replaces your state.

## Root: committed state

`Root<S>` is the single owner of committed state at a workflow boundary.

- `root.pipe(node)` runs the node from the committed state and, **only if the
  result is `Ok`**, commits its focus. On `Err` the root keeps the previous
  committed state; the returned `Err` still carries the partial state for
  inspection or logging.
- `root.state()` returns the committed value (deeply frozen).
- `root.commit(value)` commits explicitly. A `Focus`, `Ok`, or `Err` commits
  its focus; a plain object is deep-merged into the current state.
- `root.subscribe(fn)` delivers a `{ type: 'snapshot', value }` event
  immediately and a `{ type: 'commit', value }` event for each commit, and
  returns an unsubscribe function. `root.history` holds the commit events.

There is no partial commit: a sequence of five tasks commits once, after the
fifth succeeds.

## Tasks and composition

### Declaring the state type once

`berylx<S>()` returns factories bound to one state type, so you never repeat
the type parameter:

```ts
const b = berylx<Order>();
b.task(name, block)        // Task<Order>
b.asyncTask(name, block)   // AsyncTask<Order>
b.when(name, predicate)    // When<Order>
b.catch(name, handler?, options?, block?)
b.focus(value) / b.lay(value)
b.flow(value)              // Flow<Order>
b.root(value)              // Root<Order>
b.state(value)             // State<Order>
```

These return the same classes as `Task.of<S>`, `Flow.of`, `Root.of`, and so on;
there is no separate execution path. Untyped use (`Task.of(...)`,
`Focus<any>`) remains available.

### Task and AsyncTask

`Task.of(name, (focus) => ...)` is a named synchronous transition.
`AsyncTask.of(name, async (focus) => ...)` is the asynchronous form; its
callback may return a promise. Both convert ordinary exceptions to `Err`, and
both add their name to `failedNode` and `trace` on failure.

Workflows containing an `AsyncTask` must run through `EffectTree.runAsync`.
Calling one on the synchronous path (`Flow.call`, `Root.pipe`) throws rather
than returning a wrong result. Synchronous `Task`s may appear freely inside an
async workflow.

### Sequence: then

`a.then(b)` runs `b` from the `Ok` focus of `a`. If `a` returns `Err`, `b` does
not run and the `Err` is the result of the sequence. Nested sequences flatten.

### Parallel: par and Merge

`a.par(b)` runs both branches **from the same base snapshot** and joins their
results. Ordinary `Task` branches run synchronously in declaration order; in
`runAsync` all branches are started together and awaited with
`Promise.allSettled`.

Joining uses a reducer. The default, `Merge.strict()`, is a three-way join over
`(base, left, right)`:

- a branch that leaves the state unchanged does not erase another branch's work
  (`μ_b(b, x) = x` and `μ_b(x, b) = x`);
- changes to different paths, including nested ones, are both preserved;
- identical updates to the same path are accepted;
- incompatible updates to the same path produce an `Err` with code
  `merge_conflict`, `failedNode: 'parallel'`, and the conflicting path, values,
  and base in `metadata`. The result focus is the base snapshot.

`Merge.deep()` is a two-way, right-biased merge that ignores the base and can
overwrite an independent update made by the left branch. `Merge.keepLeft()`
and `Merge.keepRight()` select one side. Choose these explicitly with
`.reduce(reducer)` on a `Parallel`.

Failure policy is separate from merging. `short_circuit` (default) returns the
first failing branch's `Err` in branch order. `.accumulate()` runs every branch
and returns one `Err` with code `parallel_failed` whose `parallelErrors` lists
each branch failure.

`par()` is typed as `BerylxNode<S>`; to call `.reduce()`, `.accumulate()`, or
`.shortCircuit()` construct `new Parallel([a, b])` directly.

### Branch: When and Else

```ts
const route = b
  .when("is_pro", (f) => f.at("plan").get() === "pro")
  .then(allocateSeats)
  .or(Else.then(singleSeat));
```

`When.of(name, predicate).then(body)` is a one-arm `Branch`; `.or(otherBranch)`
appends arms. Arms are tried in order and the first matching predicate wins.
`Else` is an unconditional arm. If no arm matches, the result is `Err` with
code `no_branch_matched`. Predicates run synchronously in both interpreters and
should be pure; dry runs evaluate them.

### Recovery: Catch and rescueWith

Two forms, one handler type. A handler is either a node (run from the partial
focus) or a callback `(error, focus, perform?) => ...` where `error` is the
failure's `cause` if it has one, otherwise the `BerylxError`.

- `a.then(Catch.of(name, handlerNode | null, { fatal? }, block?))` is a
  **boundary inside a sequence**. When the preceding result is `Err`, the
  handler runs from the partial focus and its `Ok` lets the rest of the
  sequence continue. An `Ok` passes through untouched. Errors marked `fatal`
  are skipped unless the boundary opts in with `{ fatal: true }`.
- `node.rescueWith(handlerNode | null, name?, block?)` wraps a node: if the body
  returns `Err`, the handler's result replaces it.

If the handler itself fails, the result is the handler's `Err` with the
original error preserved in `metadata.rescuedError`.

### Flow and State

`Flow.of(value).call(node, handlers?)` executes a node from a raw value or a
focus and returns the `Result` without committing anywhere. It is the
"execute without a root" entry point, and the one that accepts a custom
handler map.

`State.of(value)` is a small builder in state space: `state.pipe(node)`
executes immediately, `state.and(node)` appends to a pending sequence without
running it, and `state.call()` runs the pending sequence. `root.toState()`
gives a `State` over the committed focus.

### Workflow

`Workflow.of(name, () => body)` names a composed node so that `compile()`
produces a `Graph` with that name. Run it with `workflow.call(focus)` or extend
it with `workflow.then(...)`, which unwraps to the body. A `Workflow` instance
itself is not an effect-tree node: passing it to `Flow.call`, `Root.pipe`, or
`EffectTree.dryRun` throws; use `workflow.body` there.

## Execution: EffectTree, Perform, ControlSignal

Composed nodes are not run by recursion. `EffectTree.build(node, focus)`
compiles the workflow into a darkcore `Effect` tree: each task, parallel group,
branch, and rescue becomes a tagged effect (`berylx_task`, `berylx_parallel`,
`berylx_branch`, `berylx_rescue`, `berylx_recover`) whose payload is the node
and the focus, not an opaque closure. `EffectTree.run(node, focus, handlers)`
folds that tree with a handler map. `Flow.call`, `Root.pipe`, and every
node's `.call()` go through this path with `EffectTree.realHandlers()`.

### Handler maps and Perform

Because execution is a handler map, tasks can perform **custom effects** and
the caller decides what those effects do:

```ts
const lookup = b.task("lookup", (f, perform) =>
  f.at("price").set(perform.perform("price_of", f.at("sku").get()) as number),
);

const handlers = EffectTree.realHandlers({
  price_of: (sku) => catalogue.get(sku as string) ?? 0,
});

b.flow({ sku: "A", price: 0 }).call(lookup, handlers);
```

A callback becomes effectful by **declaring a second parameter** (a third for
recovery callbacks). `Perform.perform(tag, payload)` dispatches to the handler
registered under `tag`. A missing tag throws inside the callback and therefore
surfaces as an `Err` (code `'Error'`, message `no handler for effect: …`);
so does calling an effectful task directly with no performer. The reserved
`pure` tag is rejected, and custom tags may not collide with the five
`berylx_*` tags. The same map is passed down into parallel branches, branch
arms, and recovery handlers.

`EffectTree.around(effects, (tag, payload, inner) => ...)` wraps every handler,
including the built-in ones, and propagates the wrapped map to subtrees, which
is where auditing, timing, or retry policy goes without touching workflow
definitions. `asyncRealHandlers` and `aroundAsync` are the asynchronous
counterparts.

### Dry runs

`EffectTree.dryRun(node, state)` interprets the same tree with handlers that
record task names instead of running task bodies. It returns `{ result, steps }`
where `steps` is the list of task names in execution order for that state and
`result` is `Ok` over the unchanged input. Branch predicates are evaluated
against the supplied state; parallel branches are listed in declaration order;
a rescue lists only its body, because a dry run never fails.

### ControlSignal

`ControlSignal` is an `Error` subclass that **escapes** the interpreter instead
of being converted to `Err`. Throw a subclass from a task or handler when the
host runtime needs to stop execution outright (a cancellation, a scheduler
yield); it propagates through `par`, `then`, and recovery to the caller of
`Flow.call` / `Root.pipe` unchanged.

## Inspection: Graph

`Graph.from(node, name?)` (or `node.compile()`) wraps a node for inspection:

- `nodes()` lists leaf task names in traversal order;
- `parallelNodes()` lists the task names of each parallel group;
- `toDot()` renders a Graphviz digraph with `split`/`join` nodes for parallel
  groups and labelled edges (`is_pro`, `else`) for branch arms;
- `toMermaid()` renders the same structure as a `flowchart TD` with `n0, n1, …`
  IDs and task names as labels.

## Darkcore as the effect substrate

The `Darkcore` namespace export is the bundled TypeScript port of darkcore:
`Effect`, `pure`, `op`, `perform`, `fold`, `run`, `foldAsync`, `runAsync`,
`PURE`, the `HandlerMap` / `AsyncHandlerMap` types, plus `Maybe` (`Just`,
`Nothing`), `Either` (`Left`, `Right`), `Result` (`Ok`, `Err`), `State`,
`Validation` (`Success`, `Failure`), and `IOEffects` with `VirtualWorld`. Berylx uses only the
effect core: `bind` joins tree structure, and all workflow semantics —
short-circuiting, merging, recovery, error context — live in the handlers that
`EffectTree.realHandlers()` installs. Darkcore's own `Ok`/`Err` types are
unrelated to the workflow `Ok`/`Err`.

Nothing in the tree runs until it is folded, and swapping the handler map is
the whole mechanism behind dry runs, custom effects, and `around`.

## Connecting a Root to a host: attachRoot

```ts
const detach = attachRoot<number>(root, (count, event) => render(count), {
  select: (state) => (state as Counter).count,
  skipSnapshot: false,
});
```

`attachRoot(root, listener, options?)` subscribes to a root, projects each
event's value through `select`, and calls `listener(state, event)` on the
initial snapshot and each commit. `onSnapshot` and `onCommit` receive the same
projected state for the respective event type; `skipSnapshot: true` suppresses
the initial delivery. It has no framework dependency and returns an unsubscribe
function.

## Migrating

### From 0.2 to 0.3

One breaking change, in `Parallel`. Before 0.3 the default reducer let the
right-hand branch silently win when both branches changed the same path. The
default is now `Merge.strict()`: independent updates are preserved, and
incompatible updates to the same path return an `Err` with code
`merge_conflict` instead of losing one side. If a workflow relied on right-wins,
select it explicitly:

```ts
new Parallel([left, right]).reduce(Merge.deep());
```

0.3 also introduced `Focus<S, P>` typed by state and path and the `berylx<S>()`
scoped factories; both are additive. Untyped `Task.of(...)` continues to work.

### From @minamorl/cray and @minamorl/lay

The package includes a `MIGRATION.md` for consumers of the `root-paradigm`
packages. The mapping in brief:

| cray / lay                        | berylx                                   |
| --------------------------------- | ---------------------------------------- |
| lay `Focus<S>` with mutating set  | `Focus` (immutable) + `Root.subscribe()` |
| `cray()`                          | `Task` / `task()`                        |
| sequence                          | `Sequence` / `node.then()`               |
| `parallel()` + `Reducer`          | `Parallel`, `node.par()`, `Merge`        |
| `branch()`, `else_`, `elseCray`   | `When`, `Else`, `Branch`, `Catch`        |
| `Success` / `Failure`             | `Ok` / `Err` with `BerylxError`          |
| `compile()`, `execute()`, `Graph` | `Graph.from(node)`                       |
| `toMermaid()`                     | `Graph.toMermaid()` / `Graph.toDot()`    |
| `attachCray()`                    | `attachRoot()`                           |

Behavioural differences to account for: updates return a new `Focus` instead
of mutating a store; subscriptions live on `Root`; cray's `Promise<Result>`
becomes `AsyncTask` + `EffectTree.runAsync`; failures are normalised to
`BerylxError` (`fromCrayResult` maps a string to a code, an `Error` to
name/message/cause, and anything else to code `cray_failure`); and failure
policy (`onErr`) is separated from state merging (`Merge`).
